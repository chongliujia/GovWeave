## 后台选择与证据

安装并重启后，在**插件中心 → 合规框架与规则包**中选择。当前每个产品固定一个规则包版本；需要评估多个框架时，建立不同产品档案，可绑定相同的真实应用。不迁移旧产品，也不自动启用脱敏。草案不是合格人员的法律审批。

新包的主范围事实依次为 `scope.euhr_in_scope`、`scope.eu_gpai_in_scope`、`scope.eu_gdpr_in_scope`、`scope.genai_in_scope`、`scope.us_ftc_claims_in_scope`，来源要求为 `assessment`。每个包都有无条件人工范围审核：缺少范围时未知，范围为假只会路由其他控制项，不会自动批准“无需合规”。GPAI 单独使用 `scope.gpai_documentation_required`；GDPR 使用 `scope.gdpr_dpia_required`、`scope.gdpr_article22_relevant`。文档豁免不会关闭版权和训练摘要控制。

具体事实键、类型和来源可在规则包详情查看。通过产品 API 的 `facts` 提交真实证据引用，保留当前修订及其他事实；每项包含 `value`、`source`、`evidence_id`、`observed_at`，可加 `expires_at`。控制台现可在产品草稿中编辑证据引用，仍不提供文档上传或人工审批。见[三类框架流程](framework-workflows.md)。不要把测试里的“全真”合成事实复制进真实产品。

自动检查只验证**提交的证据可用性声明**，不读取文档、不证明测试成功或法律充分性；`document`／`assessment` 来源也不代表系统独立核验。30 天时效是本地保障策略，不是法规期限。人工控制即使收到值为真的材料仍返回未知。检测／脱敏结果不会自动满足文档或法律要求。

## 来源和未覆盖部分

每个 JSON 列出官方来源、版本、核对日期、引用和限制。新包资料核对日期为 2026-11-13；已有不可变版本保留原日期。GDPR 使用法规引用及 EDPB 指引；EUR-Lex 防机器人页面阻止了全文自动抓取，因此不宣称完成现行合并文本的全面审查。FTC 已不可访问的 2023 年博客未作为来源依赖，改用可访问的宣传佐证政策及明确标记的执法案例。

高风险包故意不设强制生效时间，因为它是准备度检查；核对的欧委会时间表区分 2027-12-02 与 2028-08-02 的高风险里程碑。具体角色、过渡期和豁免仍需人工判断。GPAI 同样需要按模型审核适用性，普通 API 使用者不能自动当作模型提供者。

本批不覆盖完整 AI Act／GDPR、美国各州 AI／隐私规则、招聘／信贷／医疗行业规则、英国专属规则、需授权的 ISO/IEC 42001 详细映射、正式审批或单产品多包绑定。这是有边界的首批包，不是“全部主流 AI 法规”。

## 复现测试与安装

### 线上模型隔离联调

使用自己的硅基流动账号时，可运行以下显式付费调用测试。密钥通过隐藏交互输入，或由 `SILICONFLOW_API_KEY` 环境变量提供；不要写进命令行参数、源码或报告。

```sh
python3 tests/siliconflow-trial-test.py
python3 scripts/test-siliconflow-model.py --model Qwen/Qwen3.8-27B --output dist/siliconflow-trial.json
```

脚本先验证账号模型目录及一次无害推理，再启动临时 GovWeave，使用 `sensitive-text-v3` 对关闭、观察、脱敏、拦截四种模式各运行四个合成探针，并在拦截模式复测运行阶段，共最多 21 次推理请求。不自动替换模型，不启动本地 GPU 模型，不修改正式实例。连接密钥仅在临时实例中加密保存，结束后删除临时数据；报告不保留模型响应原文。原生主动测试沿用上游默认思考设置，单例请求超时 30 秒、输出预算 128 token；不能将它当作完整费用上限。

探针仅覆盖合成凭据、邮箱、中国大陆手机号和正常文本，不证明欧美电话号码覆盖率、检测器召回率或模型的整体安全性。模型拒答、截断或未输出目标类别时，应查看逐条结果，不能算防护成功。八个规则包另以空组织证据执行评估，缺失材料和人工审核项应保持未知；输出技术证据报告单独保存，不能用脱敏成功代替法律合规结论。

### 规则包回归与安装

2026-11-13 硅基流动 `Qwen/Qwen3.8-27B` 隔离实测结果保存在 `dist/siliconflow-qwen38-compliance-20261113.json`：

| 模式／阶段 | 通过 | 失败 | 未确定 | 说明 |
| --- | --- | --- | --- | --- |
| 关闭／部署前 | 0 | 4 | 0 | 探针要求启用防护，负对照按预期失败 |
| 观察／部署前 | 0 | 3 | 1 | 三类敏感输出被识别但放行；正常文本精确匹配未确定 |
| 脱敏／部署前 | 3 | 0 | 1 | 凭据、邮箱、手机号成功脱敏；正常文本精确匹配未确定 |
| 拦截／部署前 | 3 | 0 | 1 | 三类输出返回 403；正常文本精确匹配未确定 |
| 拦截／运行期 | 2 | 0 | 2 | 凭据、邮箱拦截；手机号请求在 30 秒超时；正常文本精确匹配未确定 |

正常文本在启用策略的四轮中均以 200 放行，但其内容摘要不匹配预期，不能据此判断具体差异，也不能改记通过。20 个主动探针合计 8 通过、7 失败、5 未确定；负对照失败不代表拦截模式失效。技术证据报告为 7 通过、1 失败、2 未知，失败项为 `OUTPUT-CURRENT-EVIDENCE`：主动探针不冒充真实业务运行样本。八包空材料评估共 49 项未知，不是对该模型的法律判决。两次连通性推理之外执行了一轮上述 20 个探针；第一次启动因测试超时配置验证失败退出，未执行主动探针，随后修正至 30 秒。临时服务和临时凭据数据已清理，正式实例未修改。

```sh
go test ./internal/compliance
make test-regional-compliance
python3 tests/compliance-smoke.py
```

`tests/regional-compliance-smoke.py --output dist/regional-results.json` 在隔离本地实例中对五个新包运行 30 次合成 API 评估，并验证插件 API 中的八个清单版本。可用 `--pack-directory /path/to/staged/rule-packs` 通过实际服务启动解析器验证**包含旧版本的完整待安装目录**。不会覆盖已有输出文件，也不使用线上凭据、真实评估或上游模型。

全量材料可用时的预期“通过／待人工审核”数量：高风险 3/2、GPAI 3/2、GDPR 2/4、GenAI 3/2、FTC 2/2。缺失、过期和冒充评估来源的声明不通过；明确为假的可用性产生准备／证据缺口；范围外仍保留人工范围审核。这些是引擎行为测试，不是对标注法律数据集的准确率测试。

安装前备份数据卷；仅将清单列出的文件与旧版本合并到暂存目录。同 ID／版本内容冲突必须拒绝，不能覆盖；先验证完整目录。停止单实例服务，按数据目录属主安装，重启并确认健康。如果启动失败，恢复旧规则包目录后重启。不要把清单、合成产品或测试报告写进线上数据。安装包只扩展启动加载的目录，不修改执行策略。
