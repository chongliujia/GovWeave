# 合成标记效果与成本离线回测

[English](../canary-benchmark.md) | **简体中文**

本工具在同一组标注合成样本上，对比四个独立检测阶段的效果和本地函数调用成本。不调用模型、不需要 API Key、不修改已有实例，也不安装响应过滤器。它是开发回放，不是生产实时 SLA 的证据。

## 运行

在源码仓库执行：

```bash
make benchmark-canary
```

也可指定语料和参数：

```bash
go run ./cmd/canary-bench \
  -corpus tests/testdata/canary-validation-v2.json \
  -output-dir dist/canary-benchmark \
  -repetitions 30 -warmup 2 -trials 2 \
  -workers 1,2 -seed 20261028 -timeout 60s
```

命令会打印新建私有报告的位置，保留已有报告。报告遵循 [benchmark.schema.json](../../schemas/benchmark.schema.json)，记录语料身份与 SHA-256、回测版本、阶段版本、参数、各轮派生种子、执行程序 SHA-256、Go 版本、操作系统／架构、逻辑 CPU 数、GOMAXPROCS 及部分构建信息。使用 `go run` 时，程序摘要标识本次临时生成的二进制，不保证不同构建可复现。比较报告前应核对环境和工作负载。

重复次数为 1–2000，预热次数为 0–20，试验轮数为 1–5；worker 模式只能从 1、2 中选择且不能重复。参考、预热、计时调用总量最多 200000。参考结果尚未算完就超时，不生成报告；预热或计时期间中断可保留 `state: incomplete` 并以非零状态退出。取消在有界检测调用之间协作进行，已开始的调用可能在截止时间后才返回。不能把部分轮次当作已完成比较。

## 四个阶段的含义

| 阶段 | 实验内容 |
| --- | --- |
| `exact` | 字面匹配，含共用输入资格检查和结果元数据 |
| `normalized` | 精确匹配加已说明的有损规范化 |
| `single_layer` | v2 的检测方法与预算，限制为一层可逆变换 |
| `two_layer` | 当前 v2 检测器，最多两层可逆变换 |

单层和两层使用相同 v2 方法与预算，预期区别是深度。`single_layer` **不是**历史 v1，后者的方法和限额不同。实验阶段版本不注册为生产检测器，也不重新解释已保存的主动测评证据。历史 v1／v2 对比仍见[标记检测与验证](canary-validation.md)。

每个阶段都独立完整检查输入；这不是已经实现的路由级联。如果未来只把部分请求交给慢阶段，还需要验证门控：前置选择可能丢掉慢检测器原本能发现的问题。不能假定阶段越深，所有结果都必然单调改善。

## 效果统计

每个阶段对每个唯一标注案例只统计一次。重复计时不增加标注样本量，也不产生新的独立效果证据。现有 48 例、72 例都已经看过并用于研发，只适合作为回归和消融数据，不再是未见验证集。

报告保留逐项状态／原因、分组统计，以及相邻阶段的变化清单：新增检出、丢失检出、新增／消除误报、新变未知和恢复可判断的案例。应检查案例清单，而不只看 TP 总数相减。

统计口径继续遵循：

- 标注为泄露的案例返回未知，召回统计按漏检处理。
- 标注正常但未知的案例不算 TN，同时展示未知和判定覆盖率。
- 没有阳性检测时，精确率为未定义。
- 误报率以全部标注正常案例为分母，必须结合判定覆盖率阅读。
- 未知泄露案例同时进入 FN 和未知细分，不能把这些列当作互斥人群直接求和。
- `unevaluable` 输入应保持未知，若得出二元结论则增加 `boundary_errors`。

两套语料的泄露比例和覆盖不同，百分比不代表可相互比较的总体估计。新模型输出、新风险家族和应用场景仍需另行取样验证。

## 计时边界

计时前，每个案例／阶段先产生一次不计时的参考结果；每轮再执行指定预热。每次遍历均使用已记录种子打乱案例／阶段组合，不同试验轮次交替 worker 模式顺序。这能减少固定顺序优势，但不控制 CPU 绑定、温度／电源状态、后台程序或操作系统调度。

计时在 worker 内、即将调用 `DetectStage` 时开始，函数返回时结束。包括输入资格检查、匹配／解码、结果元数据，以及调用期间发生的调度或 GC 停顿。两次读时钟会影响很快的阶段，报告没有扣除计时器开销。

不包括队列等待、语料读取／解析、参考效果统计、调用后的一致性检查，以及报告编码／落盘。没有计入网络、HTTP 路由、认证、审计同步、模型生成、流式缓冲或客户端接收。重复调用的阶段版本、状态和原因在计时区间外与参考结果核对。

单、双 worker 是固定并发的本机闭环工作负载，不模拟独立到达率、生产排队、突发请求或饱和状态。双 worker 下的阶段延迟，也包含混合负载中其他阶段带来的竞争。`harness_inclusive_calls_per_second` 用完成调用数除以计时批次墙钟时间，包含派发、goroutine 启动和一致性检查，并混合所有阶段。它是回放器吞吐，不是某阶段服务容量或模型吞吐；预热不计入该数值。

## 阅读尾部延迟与分组

耗时单位为纳秒，含调用数、唯一案例数、均值、最小值、P50／P95／P99 和最大值。分位数使用 nearest-rank，即排序索引 `ceil(p × n) - 1`。`p99_is_maximum` 表示选中的是最大观测的排序位置；少于 100 次调用时会如此。若有并列值，P99 的数值也可能恰好等于最大值，这本身不代表样本量不足。

逐轮摘要用于识别未完成工作及轮次波动。同一 worker 模式的汇总分位数由各次调用合并计算，不平均各轮分位数。对同一个固定案例重复很多次，不会使它代表其他输入，也不提供独立的总体置信区间。

汇总还按 group、标签、category、输入大小范围、输入是否合格、结果状态和未知原因切片。总体回放对语料每个案例等权，包括很快返回的无效输入。描述“快”之前，应先看长文本、噪声、编码和合格输入分组。小分组的 P99 可能等于其最差观测。当前报告不测每次调用的内存分配。

## 验证与用途

报告用于判断某个阶段增加了哪些检出、误报或未知，代价是多少本地尾延迟。它不选择生产阈值、不认证隐私、不建立普遍安全预算，也不证明实时阻断策略有效。零退出码表示回放一致地完成，不表示零错误或满足 SLA。

[标记检测范围](canary-validation.md)和[主动测评边界](active-assessments.md)继续适用。当前标记检测运行在主动测试中，尚未变成业务响应阻断器。结构化证据和重放仍由确定性代码完成，不依赖 LLM 或 Agent。

版本固定的插件接口，以及另行冻结语料上的实际快慢路径分流实验，见[检测器插件与分流回放](detector-routing.md)。该回放包含注册表的完整流水线成本，不能与这里的裸阶段计时直接比较。
