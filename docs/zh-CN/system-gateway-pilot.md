# 系统级网关试点

[English](../system-gateway-pilot.md) | **简体中文**

这是第一阶段实现，不是“所有内部流量已自动接管”。应用继续使用正式实例的 OpenAI 兼容接口，不要求替换为新的模型 SDK。供应商密钥只配置在网关的模型连接中，应用使用自己的 GovWeave 应用密钥。

## 已实现的链路

`examples/support-agent/app.py` 是文件知识库检索试点，不是向量数据库 RAG 或完整多 Agent 系统。每次模型请求和知识库读取均经过同一配置的网关，响应原路返回；拒绝、错误、追踪回执异常后不直连、不回退到本地读取、不自动重试。

```text
用户 → SupportAgent → GovWeave /v1/chat/completions → 模型
                    ← GovWeave 输出检查 ← 工具提议
                    → GovWeave /v1/tools/{alias}/invoke → 知识库读取服务
                    ← GovWeave 工具输出检查 ← 检索结果
                    → GovWeave /v1/chat/completions → 模型
用户 ← SupportAgent ← GovWeave 输出检查 ← 最终模型答复
```

模型输入侧现有策略是凭证检测，不是通用输入 PII 脱敏。输出处理取决于后台检测器、类别、作用范围和 observe／redact／block 模式。工具读取还受资源授权和工具策略约束。应用自身入口、最终出口及自行追加的答复内容仍需单独治理。

试点默认创建 Trace ID，以服务端 span 串联“模型 → 工具 → 模型”。协调器可以传入 `--trace-id`、`--agent-id`、`--parent-span-id`；parent 必须同时带已有 trace。它们只声明关联、不授予权限、不证明内部交接经过了网关。每个并发任务必须使用独立 SupportAgent 实例。

## 后台覆盖视图

插件中心 → 合规框架／规则包 → 选择已保存产品 → **系统数据流覆盖情况** → **刷新覆盖快照**。

管理员只读接口：`GET /api/v1/compliance/products/{id}/coverage`。

- 按当前授权列出模型、至少有一个资源授权的读取工具和独立内容检查入口；不返回端点、密钥或资源正文。
- 分开显示当前配置和实际观察状态。已配置不代表已使用；已观察也不代表检测通过。
- `runtime` 统计普通调用，`assessment.chat.completions` / `assessment.tools.invoke` 单独计入 `probes`。使用普通应用密钥进行的人工试用仍属于普通调用，不能推断它一定来自真实最终用户。
- 展示完成／未完成、阻断、失败、尝试上游调用、带追踪请求及最近观察。阻断可能发生在调用上游之前。
- 从**全局最近 100 条**记录按产品应用过滤，不是产品完整历史、固定时间窗口或流量覆盖率。审计不可用时计数为 `null`，不是零。
- 策略模式描述当前配置，不代表历史决策。最后一次运行请求无 trace 时，不展示旧请求的 trace。失败、切换产品、未保存修改或退出后不保留误导性旧视图。

应用入口／出口、Agent 内部交接／记忆、网关外检索、直连供应商始终标为未证实。成功调用或合成探测不能消除这些缺口。`/v1/content/evaluations` 是独立检查，不返回脱敏正文，也不证明调用方执行了判断。

## 正式实例接入步骤

1. 登录正式 Docker 实例后台，配置真实模型连接和供应商密钥；建立应用并授权模型。不要使用管理员凭证调用模型或把供应商密钥交给应用。
2. 部署知识库读取服务，在后台配置读取工具、其服务凭证及 resource ID 授权。网关容器必须能访问该服务。示例 `serve` 只监听宿主机 loopback；容器内 `127.0.0.1` 不是宿主机。应部署到受控可达的私有网络，不要为演示公开端口。
3. 复制 `examples/support-agent/app.example.json`，填入正式网关根地址（不带 `/v1`）、模型／工具别名和资源目录。非本机环境使用 HTTPS 并关闭 `allow_insecure_http`。
4. 安全注入 `GOVWEAVE_API_KEY`，使用不含客户数据的合成问题：

```bash
python3 examples/support-agent/app.py answer \
  --config /absolute/path/pilot.json \
  --trace /absolute/path/new-private-trace.json
```

问题从标准输入读取，输入后发送 EOF。该操作会调用真实模型并可能收费，不会创建隔离网关、修改后台产品或自动启用周期测试。`--trace` 只创建新文件、权限 0600，保存调用元数据与覆盖限制，不保存问题、工具结果、答复或密钥。答复只走应用输出通道。

5. 将应用绑定到产品，刷新覆盖视图；在请求审计／任务证据中核对同一 trace 和模型／工具调用。客户端回执不等于审计已持久化，重启后也应核对记录仍在。
6. 按[应用评估流程](../application-assessments.md)设置模型和读取工具计划。周期测试必须显式启用，测试记录与普通调用分开。使用既有报告存档／重放能力保留证据，不把瞬时快照当成完整长期审计。

## 下一阶段

接入实际应用的输入／最终输出边界及内部 RAG／Agent 路径，配合网络策略限制旁路，再做专门的路径覆盖验证。本阶段**没有新增任意应用反向代理、网络旁路拦截或通用输入脱敏**。仅修改模型 `base_url` 不能证明全部数据受治理。

本功能用于呈现运行证据和缺口；不会自动把 NIST 或其他框架的组织治理、人工审查、事件响应等控制判定为通过，也不提供合规认证结论。
