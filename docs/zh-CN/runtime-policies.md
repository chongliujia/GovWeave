# 运行时凭证策略

[English](../runtime-policies.md) | **简体中文**

当前提供一项内置策略：**敏感凭证外发 / Credential egress**（`credential-egress`）。它在调用模型前检查请求文本中的部分凭证样式，全程本地执行，不调用 LLM、云端检测服务、动态脚本或用户正则。

策略默认关闭，不授予模型访问权限，不检查模型回答，也不判定法律合规性。

## 配置步骤

1. 在“模型连接”和“应用与密钥”中配置连接及应用授权。
2. 打开“运行时策略”，选择模式。
3. 选择私钥标记、API 密钥样式或两者。即使关闭策略，也须保留至少一项规则。
4. 分别选择应用和模型范围：全部或指定对象。
5. 保存策略；已保存模式和版本号表示当前生效配置。未保存的表单不影响流量。
6. 使用获授权应用发送请求，在“调用记录”中选择请求 ID 查看检查结果。

语言切换保留草稿。“重新加载已保存策略”会用服务器配置替换草稿。过期版本保存会返回冲突，不覆盖其他页面的更新。

## 模式

| 模式 | 是否检查文本 | 命中后的行为 |
| --- | --- | --- |
| `disabled` | 否 | 不执行凭证策略，应用访问控制仍生效 |
| `observe` | 在范围内检查 | 记录规则标识，原始请求及命中的凭证仍会转发 |
| `block` | 在范围内检查 | 返回 `403 policy_blocked`，不访问上游 |

不在范围的请求记录为 `not_applicable`，不扫描文本。在范围内且无命中记录为 `allow`，不代表文本一定没有敏感数据。

观察模式适合分析误报，但不会脱敏或阻止命中内容外发。验证转发行为时请使用合成测试值。普通和流式 Chat Completions 都适用；阻断流式请求时返回 JSON，不启动 SSE。模型列表和管理员连接检查不走这个请求内容检测器。

## 适用范围

应用范围和模型连接范围取交集，必须同时匹配。

| 应用范围 | 模型范围 | 检查对象 |
| --- | --- | --- |
| 全部 | 全部 | 所有已受理的 Chat Completions 请求 |
| 指定 | 全部 | 来自指定应用的请求 |
| 全部 | 指定 | 访问指定连接的请求 |
| 指定 | 指定 | 同时满足两组范围的请求 |

范围绑定 ID，不绑定名称或别名。每组最多指定 64 个已存在且不重复的 ID。API 空列表表示全部，包括以后新增的对象；控制台选择指定范围时必须至少勾选一项，避免空选择意外变成全部。

重命名不改变范围。修改连接的上游地址或模型仍保留范围成员关系。模型授权独立检查，策略不会扩大应用原有权限。

## 内置规则

规则集版本为 **`credentials-v1`**。

| 规则 ID | 检查方式 |
| --- | --- |
| `private_key` | PEM 私钥开始标记：通用、RSA、EC、DSA、OPENSSH、ENCRYPTED |
| `api_key` | 部分带前缀样式：`sk-` 后至少 20 个令牌字符，`gw_app_` 后 43 个令牌字符，部分 GitHub 风格令牌和 `AKIA` 加 16 位大写字母／数字 |

`sk-`、`gw_app_` 的令牌字符指 ASCII 字母、数字、下划线和连字符。GitHub 风格样式包含 `ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_` 后至少 30 个字母／数字，以及 `github_pat_` 后至少 40 个字母／数字／下划线。实现对相应前缀使用单词边界检查；完整定义位于源码的 `internal/gateway/policy.go`。

这些规则只做样式匹配，不验证凭证是否真实、有效或启用，也不校验私钥材料。仅出现私钥头即可命中。示例与合成凭证可能误报，其他格式或供应商以后改变的格式可能漏检。

## 检查边界

检测原始请求 JSON 的全部字符串 token，包括字段名、重复字段、消息、工具参数和扩展字段，使用标准库解码当前 JSON 层的转义。

当前不支持：

- 递归解码字符串内部再次转义的 JSON。
- 解码 Base64、识别图片或二进制附件、下载 URL 指向的内容。
- 重组跨字段分片的凭证或识别所有混淆方式。
- 检查模型回答、拦截后续 Agent 或 MCP 工具执行。
- 通用个人信息、商业秘密、提示词注入或法律违规识别。

仍受 1 MiB 请求上限约束，检查占用现有执行槽位，不增加远程调用或响应缓冲。单次检查耗时以微秒记录；开发微基准见[开发文档](development.md#请求凭证策略验收)。

## 调用记录与失败

进入策略评估的 Chat Completions 记录包含 `content_policy`。下面是示意数据，耗时不是性能目标：

```json
{
  "id": "credential-egress",
  "revision": 2,
  "ruleset_version": "credentials-v1",
  "mode": "block",
  "result": "block",
  "matched_rules": ["api_key"],
  "check_duration_us": 80
}
```

只保存固定标识，不保存命中文本、字段路径、偏移、秘密指纹或凭证哈希。`content_policy.revision` 是独立策略版本；旧顶层 `policy_revision` 仍表示连接／应用配置版本。

| `result` | 含义 |
| --- | --- |
| `disabled` | 策略关闭 |
| `not_applicable` | 应用或连接不在范围 |
| `allow` | 已检查，没有命中 |
| `observe` | 规则命中，策略允许转发 |
| `block` | 规则命中，策略阻止转发 |
| `error` | 无法完成检查，未发送上游请求 |

访问授权 `decision: allow` 可以与策略 `result: block` 同时出现。评估前已拒绝的请求、模型列表、连接检查及旧记录可能没有此对象，控制台显示“未执行检查”。

观察到命中并不等于上游调用成功。阻断判断也可能与 `503 audit_unavailable` 同时出现：这表示无法可靠保存开始记录或预留结束容量，仍不会发送上游请求。`503 policy_unavailable` 同样不访问上游。查看记录时须结合整体结果、HTTP 状态、错误码和 `upstream_attempted`。

## 管理接口与持久化

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/policies/credential-egress` | 读取当前策略、版本和规则集版本 |
| `PUT /api/v1/policies/credential-egress` | 校验并原子保存替换配置 |

管理写入要求管理员会话、`Content-Type: application/json` 和 `X-GovWeave-Request: console`，浏览器还需通过来源校验。应用密钥不能管理策略。完整契约见 [OpenAPI](../../api/openapi.yaml)。

新策略的更新请求示例：

```json
{
  "revision": 0,
  "mode": "observe",
  "rules": ["private_key", "api_key"],
  "application_ids": [],
  "connection_ids": []
}
```

每次更新前读取当前版本；`0` 只适用于初始策略。保存成功递增版本，过期版本返回 `409`，模式／规则／范围无效返回 `400`。持久化失败保留旧策略。

最新配置以私有权限保存在 `policies.json`。损坏或不支持的状态阻止启动，缺失文件则初始化关闭状态，因此应通过保存配置关闭策略，不要删除文件。备份应包含该文件。

每次请求使用不可变快照。更改只影响新的检查，已检查的请求保留其版本。目前不保留完整历史配置、不提供完整管理员变更归因、审批流程、多条独立范围策略或法律控制映射。
