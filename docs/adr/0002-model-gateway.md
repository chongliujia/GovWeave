# ADR 0002：单实例模型访问与最小调用记录

- 状态：已采纳，2026-10-15
- 承接：ADR 0001 的部署基础；用户授权继续完成模型连接、应用密钥、普通／流式调用和记录闭环。

## 决定

使用现有 Go 服务增加一个 OpenAI 兼容的 Chat Completions 适配器。复用标准库 HTTP Transport，不建立通用路由引擎，也不引入另一个 Python 运行时或代理服务。只改写请求的模型别名，其余 JSON 参数透传；不宣称自动覆盖所有模型厂商。具体行为与限制以 `docs/model-gateway.md` 为准。

控制台提供连接创建／编辑／停用、显式连接检查、应用授权、密钥生成／轮换／撤销和记录查询。模型连接与应用均使用每记录 revision 防止并发覆盖。保留管理身份和应用身份分离，不允许管理员凭证直接推理。

当前沿用单进程文件存储，避免在预览阶段强制引入数据库部署。连接和应用保存在 0600 的 `gateway.json`；应用密钥为高熵随机值，只持久化哈希；上游凭证用 AES-256-GCM 加密，连接 ID 作为附加认证数据。加密密钥保存在单独 0600 的 `gateway.key`，须和配置共同备份。该设计不能抵御拥有数据目录和进程权限的攻击者，尚未接入外部 KMS。

## 调用记录与实时性

每个已授权上游调用先同步保存开始事件，再发起网络请求，结束时补终态。写入失败或容量不足时停止新的上游调用。单个 SSE 事件有界缓存后及时 flush，不缓存完整回答。取消和上游时限传递至 Transport；不自动重试推理 POST。

这是明确的可靠性取舍：文件 Sync 在首字节路径中，性能依赖磁盘；未来扩展为持久化批量写入或数据库事务时应测量端到端分位延迟、过载行为和崩溃恢复，不能用无界异步队列替代交付保证。128 MiB 记录上限与人工归档是预览版边界，不是最终留存方案。

允许／拒绝是应用访问控制决定。当前记录不是已验证合规证据，也没有防篡改能力。后续引入 PostgreSQL、管理员变更日志、历史策略快照、关联调用链和受审法规控制映射；这些内容不会被伪装为本次已交付能力。

## 验证边界

自动测试使用本地模拟上游，覆盖 SDK 调用、权限隔离、凭证存储、普通与 SSE 转发、取消、超时、错误脱敏、限额和重启恢复。真实厂商兼容、多实例 HA、MCP 执行、法规检测和生产性能继续单独验收。
